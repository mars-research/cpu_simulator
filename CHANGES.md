# Changes relative to upstream uiCA

Base: [andreas-abel/uiCA](https://github.com/andreas-abel/uiCA) `6ebeeab`. Goal: simulate loads that miss
the caches, calibrated on a Xeon Gold 6548Y+ (Emerald Rapids, CloudLab d760). Stock uiCA treats every
load as an L1 hit.

## 1. New target CPU: `EMR`
- Golden Cove core sizes (6-wide issue, 512-entry ROB, 12 ports) — `microArchConfigs.py:179`.
- Instruction data: uops.info's EMR measurements, generated by `convertXML.py` (`:95`).
- The scheduler's port assignment accepts 12 ports — `uiCA.py:1143`.

## 2. Two upstream dependency bugs fixed
- From ICL on, a store's data register was dropped, so values passed through memory had no dependency
  (a store→load chain ran at 1 cycle/iter) — `instructions.py:210`.
- EMR executes some `add/sub/inc/dec/lea` at rename (0 uops); their results lost the input
  dependency. They now pass it through — `uiCA.py:323`.

## 3. Execution-driven simulation (`-state state.json`, `execstate.py`)
- **State file.** The initial machine state: register values and the contents of named memory
  regions, generated lazily page by page from layers (fill, random, explicit values, a file, or a
  cyclic pointer chain), so regions can be many GiB; plus memory-model parameters. Format in the
  `execstate.py` docstring.
- **Execution.** Unicorn (an x86-64 emulator; `pip install unicorn` into `.venv`) runs the code from
  that state. Each executed instruction yields its effective addresses (computed from the registers,
  so prefetches are included) and the next instruction. The data decides the iteration count, the
  branch outcomes and the addresses. The program ends when execution leaves the code — `Execution`,
  `execstate.py:204`.
- **Front end.** Rounds (iterations, counted at `run.loopHead`) come from the executed path instead of
  repeating the body. A taken branch ends a fetch block, and fetch switches between MITE and the DSB at
  real branch targets. The LSD is used only when the last instruction is the only branch —
  `TraceRoundGenerator`, `uiCA.py:1563`; `FrontEnd`, `uiCA.py:385`.
- **Output.** Cycles per round over the second half of the rounds, totals, per-branch taken counts,
  final registers, memory-model statistics, and the uops table per round — `reportExecution`,
  `uiCA.py:2263`. Without `-state`, uiCA behaves as stock (every load an L1 hit).

## 4. Memory-system model (`memsys.py`, used with `-state`)
- **Addresses** come from the executed instance (`covers` / `addressOf`, `memsys.py:196`).
- **Caches.** L1 / L2 / non-inclusive LLC, LRU, with lines in flight tracked so a later load merges
  with an outstanding miss — `Cache` `:76`, `MemSystem` `:149`.
- **Miss handling as queues.** Fill buffers (16) and L2 misses (48) are server pools
  (`SlotResource` `:112`). Each request type (load, prefetcht0, prefetcht2) occupies a fill buffer
  for its own fitted time (`fbServiceTime`, `:64`); then the LLC/DRAM latency and DRAM bandwidth
  apply — `access()` `:229`. Parameters are in `PRESETS` (`:51`).
- **Hook into uiCA.** At dispatch, a load asks the model when its data is ready; if it needs a fill
  buffer and none is free, it stays in the scheduler and retries — `uiCA.py:1037`, `:1070`. Data
  readiness feeds the normal dependency logic — `uiCA.py:143`.
- **Optional rule (off by default):** a miss that finds every fill buffer busy goes to L2 without
  one (`fbBusyBypass`, `:59`). Hardware counters show this happens, but on its own it fits worse
  (14.9 % vs 6.7 % mean error).

## 5. Load/store queue
- Load buffer (192) and store buffer (114) on EMR; issue stalls when either is full; stores leave
  the buffer after retirement — `LoadStoreQueue`, `uiCA.py:866`, issue check `:489`.
- Store-to-load forwarding by concrete address — `uiCA.py:179`.

## 6. Tests and calibration (`tests/`, see `tests/README.md`)
- 20 short kernels (pointer chases, parallel misses, prefetch-then-load, request-type mixes) measured
  natively on the d760 (`measure.py` → `ground_truth.json`) and simulated from states set up the way
  the native harness sets up memory (`make_states.py` → `states/`, `run_uica.py`).
- `test_execstate.py` checks final registers, branch counts, instruction counts and addresses against
  independent Python computations, on kernels with data-dependent branches, a variable-length inner
  loop and a value passed through memory (`exec_kernels/`).
- Fitting: `fit_fb.py`. Hardware counter survey: `results/counter_survey.md`.

## Status
Mean error 6.8 % over the 20 tests (`run_uica.py`). Largest open gaps: prefetch then load of the
same line (`pf_t2`, −24 %; `pf_t0`, −16 %) and many parallel pointer chases (`mchase48`, +19 %).
Not modelled: branch misprediction, stores missing the cache, several threads sharing DRAM. Unicorn
has no AVX-512, so DRAMHiT's `find_batch` will need a recorded trace (Pin/SDE) in the same
per-instruction format.
